Hub web Blazor Server (`server/Shopee.Hub.Web`) điều phối fleet — heartbeat, assignment, lease, sync file, ledger. Review 2026-07-25: không có SQL injection/XSS, nhưng có mấy điểm đúng-đắn cần vá + một mớ code chết. Deploy lên VM do Fable làm SAU nghiệm thu — plan này chỉ sửa code + build.

## 3. Các bước thực hiện

### Bước 1 — Debounce ô tìm kiếm `/orders`

`Components/Pages/Orders.razor:27`: `@bind:event="oninput"` + `@bind:after="OnFilterChanged"` → MỖI phím gõ chạy `CountOrders` + `QueryOrders` (LIKE `%…%` không index) đồng bộ dưới `lock (_gate)` toàn cục của `HubDatabase` — nghẽn heartbeat/lease cả fleet. Sửa: debounce ~300ms bằng Timer (huỷ timer cũ mỗi keystroke, chỉ query khi ngừng gõ; nhớ `InvokeAsync(StateHasChanged)`), hoặc nếu vướng vòng đời Blazor thì chuyển sang tìm khi Enter như `ProductGridPanel`. Giữ nguyên hành vi lọc.

### Bước 2 — Hằng hoá chuỗi cờ `'hết nhịp…'`

`Data/HubDatabase.Assignments.cs`: chuỗi `'hết nhịp (máy nhận có thể đã thoát)'` được GHI ở dòng 33 rồi SO SÁNH equality ở dòng 46 (hồi sinh) và 469 (resume-mine) — sửa wording 1 chỗ là gãy âm thầm. Sửa: `private const string StaleSweepError = "hết nhịp (máy nhận có thể đã thoát)";` dùng cho cả 3 chỗ (giữ NGUYÊN giá trị chuỗi — DB đang có dòng mang giá trị này).

### Bước 3 — Render `List<>` xuyên thread

- `Services/RewriteJobService.cs:240-249` (`Say`) mutate `job.State.Log` dưới `_gate` riêng, nhưng `Components/Pages/Fleet.razor:330-334` `foreach (rw.Log)` khi render không cầm lock → nguy cơ `Collection was modified`. Sửa: expose snapshot (`lock (…) return Log.ToList();` — property hoặc method `LogSnapshot()`), Fleet.razor render qua snapshot.
- Tương tự `LoginState.Log` (append trong `BigSellerLoginService.Say`) render ở `Components/Shared/AccountConfigPanel.razor:42` — cùng cách sửa.

### Bước 4 — Transaction cho thao tác nhiều-statement

- `Data/HubDatabase.Shops.cs:126-141` (`DeleteShop`: xoá orders rồi xoá shop) và `Data/HubDatabase.Machines.cs:64-97` (`ResetMachineWork`: 4 lệnh rời): bọc `BeginTransaction`/`Commit` — crash giữa chừng không để trạng thái nửa vời.

### Bước 5 — Siết ForwardedHeaders + prune rate-limit

- `Program.cs:110-116`: `KnownNetworks/KnownProxies.Clear()` khiến mọi nguồn spoof được `X-Forwarded-For`. Sửa: thay bằng `KnownNetworks.Add(new IPNetwork(IPAddress.Loopback, 8))` (chỉ tin proxy loopback — cloudflared chạy cùng máy).
- `Auth/LoginRateLimit.cs`: `_hits` không bao giờ prune IP cũ → rò bộ nhớ chậm. Thêm prune entry quá hạn (mỗi lần ghi hoặc timer đơn giản).

### Bước 6 — Xoá code chết đã chắc chắn

Trước khi xoá TỪNG mục: grep toàn repo (gồm `suite/`, `orders/`) xác nhận 0 caller.
- Endpoint `GET/POST /dispatcher` (`Api/ClientApiEndpoints.cs:208-214`) — web UI inject `DispatcherService` in-process, không qua HTTP.
- Endpoint `POST /products/import-xlsx` (`Api/ProductApiEndpoints.cs:116-133`) + `GET /products/export-xlsx` (`:136-143`) — web dùng in-process; chưa từng có client gọi. (Hằng `HubRoutes.ProductsImportXlsx/ExportXlsx` nằm bên `suite/Shopee.Core` — KHÔNG đụng, plan khác dọn.)
- `HubDatabase.GetShop(long)` — `Data/HubDatabase.Shops.cs:45-55`.
- `FleetStateService.Presence(DateTimeOffset)` — `Services/FleetStateService.cs:102-108`.
- `RowRangeMath.MaxRow` + `Complement` — `Data/RowRanges.cs:18,44-61` (bản copy phía server; chỉnh comment đầu file cho khớp).
- 8 key `HubIcons` mồ côi: `stats`, `bigseller`, `tag`, `scrape`, `import`, `update`, `check`, `x` (`Components/HubIcons.cs`).

### Bước 7 — Gắn log cho 4 endpoint HOÃN xoá

`GET /api/shops`, `GET /api/orders`, `POST /accounts/append`, `POST /accounts/remove` (`Api/ClientApiEndpoints.cs:130, 198-205, 106-116`): repo không còn ai gọi nhưng client CŨ ngoài fleet có thể còn. KHÔNG xoá đợt này; thêm 1 dòng log (`logger.LogWarning("legacy endpoint hit: {path} from {ip}")`) ở đầu mỗi handler để thu bằng chứng, xoá ở đợt sau nếu log im.
